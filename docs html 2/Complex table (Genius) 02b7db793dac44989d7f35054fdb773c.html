The Complex table (Genius) is used to view, sort or filter records in a database.

Genius provides two ways to view records: either as a list or as a table. The list view presents each record as an accordion item. When clicked, the accordion opens. Within the open accordion, the the record attributes and values are visible. Also presented are action buttons (typically one to three buttons).

List view

  • available on all screen sizes.
  • this has been built and can be used.

Table view

  • this view is not available on mobile and the toggle disappears.
  • due to built in 2023.

Elements

  1. Action bar (optional) – this is the tinted bar that appears above the list, allowing users to perform actions on the records below. Download, Sort, Filter, Settings and toggle between table view and list view.
  1. List view – in this view, the records are shown in an accordion.
  1. Table view - in this view, the records are shown in a table. The page scrolls left-right and up-down. Each record has a single clickable hit area, that takes the user to a record details page.
  1. Total number of records - appears at the bottom.
  1. Pagination - can be used to spilt up the content.

Action bar

The action bar is a complementary component and has a set of actions that affect how the component is displayed. It can also be used with actions that take users to a different page or flow.

On a mobile it collapses into one button with all actions. If a users clicks that button it should open a drawer. In some instances, it may support one other button that takes the user to a different page or flow, but it won’t have more than two buttons.

If the user tick multiple checkboxes in the genius component, the action bar will add a “bulk selection” option below.

If there are some functions applied from the action bar options these will be shown by using our tag component. If the user ticks multiple checkboxes the tags will be shown below the bulk selection.

The tags are always inline, but will stack if their content is too long.

Validation

Within this component validation can happen in two ways

  • Multiple data with one or more errors where we need to tell the user where they happened and how to fix them.
    • This component can support 2 badges: Warning and Success. These are optional.
    • Eg. File upload
  • Action history page should show users both errors and successes together.
    • This component supports our 3 badges: Fail, Success and Warning.
    • Eg. Upload history

Drawer

  • The drawer component is a panel that contains extra information and/or actions.
  • The drawer is dependant on other components and it is only visible if the user takes an action.
  • The drawer can be used in conjunction with other components such as text, text links, buttons, accordions and inputs (general).
  • Accordions used inside the drawers will always have an input action. This could be a text input, checkbox, radio, dropdown, etc.
  • On desktop, this component is always right aligned and slides from the right when the user initiates an action. Users can close it by clicking a button or clicking anywhere outside of the component or completing an action.
  • On desktop, buttons always align inline and on mobile they will stack.
  • On mobile, this component takes the whole screen. The only way for a user to close it would be by clicking on the close button or completing an action.
  • This component is currently used with our action bar component.
