Drawer

Storybook link

A drawer is a panel with content that slides onto the screen from an edge. Drawers interrupt a user's journey by design. When active, a user cannot return to original page content without completing the required action or dismissing the drawer. Drawers are most commonly used for simple, short tasks that don't occur often.

Use when

Drawers are customisable components that are relevant in many contexts. Here are a few common use cases:

  • presenting options that are secondary to the page content
  • confirming a user decision
  • requiring an immediate response

Variants

There are two variants of drawer, depending on how they're triggered.

VariantsPurpose
AutomaticAppears automatically and users must select a call-to-action to dismiss it.
TriggeredAppears when triggered from a previous call-to-action.

Elements

The elements on a drawer are flexible depending on the design context. The most common include:

  1. Title (optional)
  1. Description (optional)
  1. Call-to-action (optional)
  1. Close icon (optional)
  1. Form field (optional)

Guidelines

  • Use drawers sparingly. They're disruptive and can be frustrating for users when used too much.
  • Keep drawer tasks as simple as possible. Consider using another pattern if the amount of content or features may need to increase in that context in the future.

Behaviour

Overlay

The drawer always appears on top of the original page content. On mobile, the drawer covers the entire screen. This requires users to either move forward in their journey by selecting a call-to-action or the close icon.

On desktop, the drawer covers a minor portion of the page. This leaves the original content visible but preventing users from interacting with it while the drawer is open.

Direction

On mobile, drawers always slide inwards from the right edge of the screen. While on desktop, drawer can appear from any screen edge.

Dismissible

To dismiss a drawer, users can:

  • select the original page content (on desktop only)
  • select the close icon
