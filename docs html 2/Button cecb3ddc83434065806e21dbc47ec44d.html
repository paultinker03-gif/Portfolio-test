Button

Figma linkStorybook link

A button triggers a single action.

A button should:

  • provide a simple label of a single action or next step
  • trigger a single action or next step

Use to

  • Signpost an interaction
  • Indicate an action is loading

Don't use to

  • Navigate between pages. Use a text link instead.

Variants

The visual design of the button defines its purpose and place in our information hierarchy.

Purpose
Primary• principle call to action on the page
• should only appear once per page.
• some situations do not need a primary button, for example, "Continue" or "Save" buttons
Secondary• for secondary actions on each page
• can be used without a primary button, for example, "Edit" or "Back"
Tertiary• For less important and less prominent actions.
Negative• used for destructive actions on data, for example, "Delete" or "Cancel"
• the negative button has three styles: primary, secondary and tertiary

Elements

  1. Container – Defines the variant and purpose
  1. Label – Signposts the action
  1. Icon (optional) – Can be used instead of a label or in addition to a label

Visual

Alignment

Centre-align the label in a button container.

Placement

Placement helps the user scan the page using the Reading flow.

  • match alignment with the body content
  • on mobile vertically stack buttons and place the primary button at the bottom
  • on desktop align the buttons inline and right-align the primary button

Group variations

Other components have different alignment rules:

  • Sticky footer
  • Alert dialog

Sizes

Button sizePurpose
smallFor when there's not much space to use, such as within other components. For example, the sticky footer on mobile or the genius action bar on desktop.
medium–mobileDefault option for mobile.
medium–desktopDefault option for desktop.

Spacing

Always use md (16px) between buttons within a group. Same whether they're vertically or horizontally stacked.

Button groups within other components may have different spacing rules. See Sticky footer and Complex table (Genius) for more details.

Icons

There are two options for adding icons to buttons:

VariantPurpose
Icon and labelIcons only appear to the left of the label. The only exception is the primary navigation button so that it remained anchored in every language.
Icon onlyThere are two versions: square and round. Square is currently used on the text input and alert dialog. Round is currently only part of the tag.

Behaviour

States

Button statesPurpose
DefaultUser hasn't interacted with the button yet.
HoverUser has moved their cursor over the button touch target.
FocusUser has selected the button using their keyboard.
ActiveUser is currently selecting the button.
LoadingUser has initiated an action that's requesting data from the back end and will delay slightly. It will redirect after loading.

Content

  • The label is the most important element on a button, so they need to be as clear as possible.
  • Keep button labels short and concise.
  • Focus on the action the user can take.

Pattern

Where there is an action heading, use the same verb that’s been used in the heading. For example, the primary button should start with “Edit” if the page heading is “Edit personal details”.

PatternExample
VerbContinue
Back
Verb the nounAdd new mandate
Change password
Edit personal details
Verb nowDownload now
Verb your nounComplete your declaration
Send your request

Standard button labels

Some standard terms we use on buttons:

  • “Back” – not “Previous” or “Go back”
  • “Continue” – not “Next” or “Proceed”
  • “Edit” – not “Change” or “Amend”
  • “Start”
  • “Cancel” – not “Quit”
