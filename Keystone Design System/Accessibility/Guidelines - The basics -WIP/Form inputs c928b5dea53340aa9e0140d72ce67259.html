Form inputs

Button, checkbox, file, hidden, image, password, radio, reset, submit, and text are some of the common input types on a form. To make the form inputs accessible, consider the following:

Focus Styles:
Ensure that form inputs are visually distinct when focused, making it easier for keyboard users to navigate and interact with the form.

Error Handling:
Clearly communicate any errors in the form, ideally near the problematic input, and provide instructions on how to correct them.

Keyboard Accessibility:
Ensure that all form elements can be interacted with and navigated using only a keyboard, without relying on a mouse.

Testing with Screen Readers:
Regularly test the forms with screen readers (e.g., JAWS, NVDA, VoiceOver) to identify and address any issues.

Mobile Responsiveness:
Ensure that your forms are responsive to different screen sizes and orientations.

Provide Descriptive Text:
Use additional text, such as placeholders or hints, to provide more information about what's expected in each field.

Labels and hint text

As much help as is needed is offered to prevent triggering a form error; the form label may be enough, but hint text may also be required.

More specific guidance on copy in forms can be found in UX writing guidelines for labels for 3.2.4 Level AA Consistent identification.

Identify Input Purpose

The purpose of form fields can be identified by the browser, so that auto-complete suggestions can be offered in a dropdown.

Autofocus

Focusing automatically on a form control can confuse people using screen readers. When autofocus is used, screen-readers move their user to the form control without warning them beforehand.

Autofocus can cause a page to scroll on load when automatically focusing on a control. The screen reader will announce the label to the user of the form control receiving focus, however the screen reader will not announce anything to the user before the label.

Ensure forms are GDPR compliant

GDPR is used for relying on consent as the legal basis for processing. Forms need to be GDPR compliant so this allows the user to know what they're signing up for so they can give informed consent. Here are some points to them GDPR compliant:

  • Use clear and straightforward language
  • Give the company name
  • Avoid pre-ticked checkboxes
  • Separate consent requests from terms and conditions
  • Make it easy to withdraw consent
  • Keep valid records of the consent collected
